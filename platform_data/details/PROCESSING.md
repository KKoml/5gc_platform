# Processing detail. Association, alignment and data-product construction

## D.1 Session association and temporal aggregation

[PROCESSING_LINEAGE.csv](../tables/PROCESSING_LINEAGE.csv) binds source records, processing programs/versions, rules, outputs and field ranges. Each pinned file hash is in `manifests/IMPLEMENTATION_REFERENCES.csv`; the later repair program has a separate source/published hash record. Source acquisition, offline export and model-input construction are different stages.

**Session association.** `export_session_map.py` recognizes the SMF `SessionMap` extension and older context lines, normalizes timestamps, and joins evidence within a default 15 s correlation window. SUPI and PDU session ID supply the session identity; DNN/S-NSSAI, UE IP, selected SMF/UPF and TEIDs support attribution. Session IDs can repeat across UE contexts or time and IP/TEID can be reused. Row-level `label_source` and source paths retain producer provenance, but do not distinguish every field-level direct, temporal, path-based or configuration fallback decision; unresolved fields remain null. The sample has `selected_amf=null`; this is not filled merely because the deployment is known. No source implies full current per-instance UE ownership counts.

**Packet/flow processing.** `parse_pcap.py` uses tshark-derived packet fields and creates capture-family flow/summary/time-series products. N3/N4/N6/SBI and remote UPF captures remain different observation points; duplicated traffic must not be blindly summed. N6 logical-flow handling and session mapping attach entities where evidence supports them. Packet timestamp/length, five-tuple, TEID and first/last-seen have different granularities. Some saved flow first/last-seen strings omit a UTC offset and reflect the decoder/local-time convention; they are preserved as original strings in the examples. Their timezone must be bound through the original run/decoder context before a cross-source UTC join, rather than assuming that the displayed strings are UTC. Captures use the saved 256-byte snap length; observed packet length versus saved capture length must be distinguished.

The frozen flow matcher builds whole-run IP/TEID lookup tables with last-entry replacement and no explicit session-lifetime constraint. Its `authoritative:session-map` label names that lookup route, rather than independent truth. [The measured association evidence](../quality/association/README.md) reports session rows, retained capture-summary populations and systematic flow-file sample routes separately; capture points and logical derivatives are not pooled into unique connections.

**Base time alignment.** `export_model_timeseries_csv.py` computes UTC bucket boundaries by flooring epoch seconds to the chosen bucket size, initializes the span from observed minimum/maximum timestamps, counts events and combines asynchronous source values. Original timestamp/age metadata are retained where supported. Its `apply_snapshot_series` holds the last snapshot in subsequent buckets; a regular 1 s output does not establish 1 s raw sampling or a new physical measurement. Event increments, state snapshots and complete-flow-derived interval quantities must not all be described as the same interpolation operation.

The historical exporter uses completed flow first/last times, total duration and bytes to allocate some flow quantities across intersected buckets. That is an offline summary; the flow's final record may include information unavailable at an earlier forecasting cutoff. Run-level splitting or training-only normalization cannot repair sample-construction leakage. This is why the unchanged historical 81-column product and later prefix-limited task views are separately named.

**Historical field corrections.** In W1, N3 `OT` is total observed bidirectional bytes times eight per one-second capture bucket; the exporter also writes it into `n3_uplink_bitrate_bps`. The two columns are aliases in the screened dictionary, and adding the supposed uplink to downlink double-counts downlink bytes. Control-plane success rates are cumulative percentages, not 0–1 ratios or per-second event rates. `tun_up_time` is an ISO timestamp. RTT/loss names refer to legacy packet heuristics rather than independently measured end-to-end quantities; they remain in the compatibility/crosswalk records. The original tables are unchanged.

**V3 formation.** `export_v3_timeseries.py` reads model buckets, saved plan, actual Core/access timelines, manifest and gate evidence, then emits exactly `V3_COLUMNS` from `v3_schema.py`. N3/N4 fallback and UPF-interface substitutions have explicit coverage provenance. Planned and observed intervention windows remain distinct. Formal paired validity depends on actual overlap and recovery/quality constraints, not merely a planned flag. Final quality audit can refresh V3/gate output; it does not retroactively alter raw observations. The published sample is selected from the existing source table, not reconstructed from copied excerpts.

**Business aggregation.** The base exporter computes a 60 s terminal-outcome window with at least twenty outcomes and exports gold, silver and aggregate sidecar results. Completion is success / (success + failure), with timeout/error treated as terminal failures. Low-sample windows remain empty and are not carried forward. This rule differs from recovery gating (minimum fifteen per tier/window, two windows and guard). The run-wide transfer summary is not a dynamic time-series replacement.

`export_per_nf_timeseries.py` creates per-NF products. Its session/UE associated sets are cumulative additions in the frozen implementation; they must not be interpreted as contemporary active-user ownership. Other communication, session-recovery and report products have their own schemas and should not be forced into the 81-column contract.

## Processing quality, final task inputs and handoff

The [direct platform quality evidence](../quality/README.md) adds all remote-clock probe distributions and their uncertainty, original-SMF-log field corroboration, route counts with explicit sample denominators, and availability/freshness limits. The 15 s correlation window and residual-based `clock_skew_ms` are not event-alignment errors; actual precision/recall and field-level direct/fallback decisions remain unmeasured. No downstream model score is used as a platform-quality measure.

Run quality, long-run stability, endurance, prediction-readiness, file transfer, publication checks and anonymous access are separate verdicts. A campaign-accepted run does not certify every field, online causal availability or external retrieval. The coverage table preserves observed missingness and original producer statuses.

The legacy 400/215 catalog is a cross-mode platform capability inventory. The current [W1-specific dictionary](../dictionaries/W1_FIELD_DICTIONARY.csv) is screened against actual W1 artifacts, with [all 400 decisions](../dictionaries/W1_FIELD_SCREENING_400.csv) preserved. Unsupported fields and templates are excluded from its count; historical manuscript identity remains separate.

**Core24.** The contributed final feature configuration, AE detection configuration and SAITS configuration agree exactly with the Core-side candidate's ordered 24-variable list. The six interface fields belong to the local `upfgtp-silver` interface; they are not six independent interfaces. Source streams are NF resources, host resources, interface counters and NF state. [Current handoff checks](../../checks/current/appendix_review_handoff.json) recompute provided input hashes and compare feature order. [Core handoff](../../manifests/core_handoff.csv) retains original/provided hashes, conversion and the unconfirmed historical-paper identity. Feature agreement does not establish a direct 81-column projection/resampling or reconstruct omitted original query/ingest timing.

**Prediction.** The contributed `T1_history`/`T1_targets`, frozen target/run indices and [prediction handoff](../../manifests/prediction_handoff.csv) are the final input contract. They are separate from the old 81-column product. The later Core-side repair version/hash and D06 source manifest support matching, while the experiment-side `prepare_repaired.py` has its own recorded version/hash. Prefix reconstruction restricts history sources to times before each cutoff; target windows are separate. The existing input documentation retains unresolved online source-availability details, and historical paper identity is still unconfirmed. File-hash agreement does not remove those boundaries.

**Current task/evaluation settings.** See the [canonical Appendices C and D](../../manuscript_supplement/README.md), [detailed task construction](../../appendix/D3_data_construction.md), [actual model hyperparameters](../../appendix/E1_models_hyperparameters.md) and [lineage limits](../../appendix/LINEAGE.md). Actual split IDs, numerical seeds and exact features are present; no model was fitted or replayed during this appendix reorganization.

**External raw delivery.** The full seven non-PCAP runs and retrieved current traffic corpus are backed up in the owner's private Drive. This Git directory provides source inventory and anonymized samples; complete anonymous raw retrieval and trace redistribution rights are not established. PCAP remains local and excluded. Source references identify processing rules without distributing platform acquisition/control/export source code.
